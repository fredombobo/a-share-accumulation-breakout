## 一、日常选股（每天用）

### 启动
1. 双击 `一键启动.bat`
2. 浏览器自动打开 `http://127.0.0.1:8001/`
3. 点页面上的 **「扫描」** 按钮
4. 等 5~15 分钟出结果

### 看结果
| 你看到的 | 含义 |
|----------|------|
| **A 池** | 严格筛选，优先看 |
| **B 池** | 放宽观察，不当主推 |
| **A 池空 + 显示「防守」** | 市场弱，正常风控，不是坏了 |
| 数据日期旧 | 再跑一次一键启动做同步 |

每只股票附带交易卡片：止损价、目标价、建议仓位。

### 停止
双击 `停止.bat`，或 Ctrl+C 关窗口。

## 二、离线研究维护（非日常功能）

8001 发布产品不再提供策略实验室、交互式回测台或机构控制台。日常用户不需要调参数，也不能把
探索性结果晋级为 A 池信号。

PIT、防未来函数、含成本回测、OOS/WF、基线、容量和不可变报告仍保留为离线底座。只有维护者在
提出并预登记新的经济机制后才运行；失败结果必须保持 `FAIL/NO_CANDIDATE`，不得自动生成订单。
历史定义和证据见 `docs/RESEARCH-ROADMAP.md`、`docs/ENTRY-DEFINITION-V1.md` 及历史验收记录。

## 三、历史纸面交易（指定开盘日）

### 引导模式（默认）

1. 进入 **“纸面交易”**；首页根据服务端账本只推荐一个下一步动作。
2. 没有账户时，输入“当前可用现金”创建账户。该金额不是总资产，也不会倒扣期初持仓。
3. 选择日期、输入股票和数量，点 **“检查并预览”**。日期选择器限制在本地账本和行情允许范围内。
4. 预览会从后端返回标准代码、决策日、成交日、开盘行情、滑点、逐项费用、预留现金、成交量上限和风控结果；前端不自行计算账务。
5. 点 **“确认模拟订单”**，再点 **“按日期开盘模拟成交”**。成交后直接查看现金、持仓市值、总资产和对账结果。
6. 卖出从持仓行点 **“模拟卖出”**，代码和可卖上限自动带入；T+1 不可卖时按钮禁用。

引导模式中，历史买入持续标记为练习，不代表 A 池信号。A 池自动草稿、异常对账和待成交订单会由“今天要做什么”卡片优先提示。

### 隔离演练

“第一次使用演练”使用本地真实历史行情和固定 10 万元演示资金，只调用只读订单预览。运行前后 `pt_*` 业务表、账户现金、订单、成交和持仓都不变化。

### 专业视图

点“专业视图”保留原账户、订单、成交、导入、对账、门禁、设置和公司行为工作台。

限制与提示：

- 所选日期必须是交易所开市日，且该标的在本地数据库中有当日开盘行情；周末如 `20260801` 会返回 `NOT_TRADING_DAY`。
- 历史手工演练不要求 A 池信号，但只属于纸面仿真，不会进入 A 池，也不会向券商下单。
- 决策时点固定为所选开盘日前一个交易日收盘后，预交易估值只读取该时点以前的行情。
- 已存在真实仿真成交时，只能从最后成交日之后继续；没有成交的旧日结属于派生状态，可在确认历史订单时标记为待重算。
- 创建草稿后仍必须手工确认，再运行同一模拟成交日的日结，才会产生持仓。

## 四、参数管理（可信候选隔离）

可信报告 PASS 后只写入 `research_candidates` 隔离区，不会自动写入 `strategy_params.active`，也不会改变 A 池评分、创建纸面订单或真实订单。

### 状态流转
```
legacy_unverified（旧参数，仅审计）
trusted PASS → research_candidates.isolated（隔离候选）
```

| 状态 | 触发条件 |
|------|----------|
| legacy_unverified | v11 前没有可信报告关联的旧 active/candidate |
| isolated | 可信门禁 PASS，仅供人工复核 |
| reviewed/rejected | 后续人工治理状态；首版不自动进入生产 |

### 权重回灌
旧 active 已迁移为 `legacy_unverified`，`active_weights()` 不会读取。研究结论与生产扫描、A 池和纸面交易保持隔离。

### 查看当前参数
```bash
C:\Python314\python.exe strategy_store.py --weights
```

正常安全状态应为空字典 `{}`；历史记录保留在数据库中用于审计。

## 五、数据维护

### 日常同步
一键启动时自动增量同步，无需手动。

同步范围包括个股日线、日指标、资金流及 `000300.SH` 风险基准。可用
`python sync_daily.py --days 730 --moneyflow-days 10` 手工补跑；命令只有在各数据源
请求完成后才返回成功，基准指数缺失会阻断真实数据门禁。

### 历史扩容（需有效 Token）

**第一步：更新 Token**
1. 去 https://tushare.pro 个人中心复制新 token
2. 打开项目目录下 `.env` 文件
3. 替换 `TUSHARE_TOKEN=` 后面的值

**第二步：跑扩容**
```bash
# 先停掉 Web 后端（避免数据库冲突）
C:\Python314\python.exe sync_history.py
```
- 断点续传，约 2~4 小时
- 目标：3 年日线（≥720 交易日）

**第三步：验证**
```bash
C:\Python314\python.exe sync_history.py --check-only
```

## 七、常见问题

| 问题 | 解决 |
|------|------|
| A 池为空 | 看是否显示「防守」，是=正常风控 |
| 数据日期旧 | 再跑一次一键启动 |
| Token 报错 | 去 tushare.pro 换新 token 更新 .env |
| 端口 8001 被占 | 先双击停止.bat，再启动 |
| 扫描很慢 | 首次建库 30~90 分钟，日常 5~15 分钟 |
| 历史买入提示 `NOT_TRADING_DAY` | 换成真实开市日；例如 `20260801` 是周六 |
| 历史买入提示缺少行情 | 选择本地日线覆盖范围内、该标的确有行情的交易日 |

## 八、系统架构简图

```
用户 → Web UI (:8001)
         ├─ 每日选股 → 扫描 → A池/B池 → 个股证据
         └─ 纸面仿真 → 订单 → 历史开盘撮合 → 持仓/对账

离线维护（不在日用 UI）
         ├─ PIT / 数据门禁 / 防未来函数
         ├─ 含成本回测 / OOS / WF / 基线 / 容量
         └─ 不可变研究报告（FAIL 时禁止晋级）
```

日用闭环：数据同步 → 扫描 → A 池证据 → 人工判断 → 纸面仿真 → 持仓与对账。
