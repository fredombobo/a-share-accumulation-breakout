## 实施顺序与影响文件

1. 日用入口：`daily_run.ps1`、健康接口、`Topbar` / `Sidebar`。以产品、绝对目录、数据库与构建身份验证服务；默认不执行纸面日清和机构门禁，保留显式运维选项及独立备份。纠正数据日期显示。
2. 研究样本：`professional_grid.py`。固定种子、按市场和行业分层；显示总体/样本构成与当前分类局限。明确指定代码不静默截断。冻结请求版本，旧任务不改写。
3. 数据范围：新增只读研究数据就绪度服务，区分可浏览历史和具备时点记录的研究历史；核对所需指标预热区间。禁止猜测补写历史 available_at。
4. 结果解释：组合引擎保留选中参数的逐日权益、成交、月度收益、个股/行业贡献、退出原因与阶段统计；WF 零交易给出可核查原因，不补造交易。不为全网格保存巨量明细。
5. 使用与交付：同步手册、任务状态、真实宣传功能清单；修复质量门问题，恢复前端依赖，运行离线门和真实 8001 浏览器验收，提交并推送当前 origin。

## 验收标准

- 数据同步→同日期扫描→首页展示可完成；已运行服务不因 Windows 虚拟环境转发进程误判。目录/端口/数据库身份不符仍拒绝。
- 默认日用命令不产生纸面账本或 soak；操作失败返回非零退出码。
- 相同数据、种子和选择得到相同样本；默认样本覆盖沪深市场，显示分层分布；历史分类不冒充 PIT 成员。
- 历史来源/时点缺失显式报告；研究范围包含预热检查，缺失范围不得被静默使用。
- 权益和成交来自原组合会计；净收益与既有指标逐分复算一致；旧结果显示“未记录”，不推测曲线。
- 零交易与低于最小样本分别解释，原策略门槛及研究失败结论保留。
- Pytest、Ruff、Mypy、严格架构、前端测试及构建通过；桌面与窄屏人工浏览器验收。
- GitHub 仅提交代码、文档与构建产物，不提交凭据、本地行情/个人数据。

### 云端兼容性补验

首次云端运行发现 Windows 不检查的 `bootstrap.py` 可执行权限遗漏，已在 Git 中补齐 Linux 执行位。其后 Ruff、Mypy、严格架构和前端检查通过；离线 Pytest 收集时发现 SDK 初始化依赖非空 Token。CI 测试步骤现显式使用无效占位值及 `.invalid` 网关，业务请求由原测试替身验证，不上传本机凭据，不代表真实供应商门禁通过。正式数据同步配置、策略计算、研究结果与账本均未因此修改。

Linux 后续已通过 1,149 项测试，另外两项备份恢复契约因缺少 `powershell` 命令失败。CI 现将 runner 自带的 `pwsh` 暴露为该兼容命令，并显式提供临时目录；保留两项原测试和全部断言，没有用跳过测试取得通过。
