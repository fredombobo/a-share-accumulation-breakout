# Lab 可信报告与任务恢复设计

## 目标

策略实验室必须让个人用户在离开页面后仍能找回正在执行或已经完成的研究任务，并只依据净成本、样本外、滚动验证和基线对照给出可复述结论。

## 关键约束

- 一个实例同一时间只运行一个 Lab 任务；任务状态以 SQLite 为准，内存状态仅用于加速。
- 页面加载、浏览器重新获得焦点或标签页恢复可见时，都查询无 `task_id` 的状态接口；接口优先返回活动任务，其次返回最近终态任务。
- 研究阶段固定为 `IS -> OOS -> WF -> BASELINES -> GATE -> REPORT -> CANDIDATE`，阶段完成后保存检查点。
- 排名、晋级和报告主结论只使用扣除成本后的指标。毛指标仅作为诊断信息。
- 仅自动选择的 full 数据研究可给出可信结论；手工窗口、单参数和非 full 数据均标记为探索性或证据不足。
- IS 第一名在查看 OOS 前冻结为主候选；第二、三名只用于敏感性说明，不能事后替换主候选。
- 通过门禁只会生成隔离的候选参数，不会成为活动参数，也不会写入 A 池或纸面订单。
- 旧 `active` 参数若没有可信报告关联，迁移后标记为 `legacy_unverified`，保留审计但不再参与生产评分。

## 可信门禁

主候选必须同时满足：

- OOS 净交易数不少于 30、净 PF 不低于 1.0、净胜率不低于 30%、净最大回撤不高于 25%。
- 三个 WF 窗口均有完整结果、每窗净交易数不少于 30、净最大回撤不高于 25%，测试窗平均净 PF 不低于训练窗平均净 PF 的 80%。
- 在相同 OOS 窗口、股票池、持有期、名义本金和成本模型下，主候选净平均收益同时优于固定种子随机基线与 MA20/60 基线。

结论只有 `PASS`、`FAIL`、`INSUFFICIENT_EVIDENCE`。报告必须解释阻断项，成功也只能表述为“允许作为候选参数”。

## 报告与恢复

报告包含结论、样本和版本、固定成本口径、IS/OOS、三窗 WF、双基线、门禁检查表以及 IS 第二/三名敏感性。提供历史列表、JSON 与 Markdown 下载。

服务重启后，未完成任务保留阶段和检查点并标记为可恢复；再次提交相同输入从持久化记录恢复。相同输入已有完成报告时复用缓存，只有显式 `force=true` 才重算。
