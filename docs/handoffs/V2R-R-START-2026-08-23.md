## 任务定义

完成标志是“同一身份下的证据包完整、可复算、可用人话复述”，不要求策略强行 PASS。冻结 `mode=grid`、`max_codes=600`、`step=5`、自动 IS/OOS、完整成本、随机与 MA 双基线。不得改门槛、删失败窗或只保留最佳报告。

## 数据安全

1. 先只读记录真实库绝对路径、大小、fingerprint、latest date、交易日数量、代码 SHA、配置 hash。
2. 不得迁移或写生产库。若研究入口会写 DB，先制作显式副本或停止并在 handoff 报告阻断。
3. 研究产物写入本 worktree 的 `runtime/v2/research_*`；不写纸面账户、订单、成交或任务板。
4. 如果数据不是 full/不足 730 交易日，提交 `INSUFFICIENT_EVIDENCE` 及缺口，不得伪造行情或改为小样本宣称可信。

## 执行顺序

1. 保存 preflight JSON；确认没有已有运行任务。
2. 只提交一次冻结请求并保存 task_id；之后只查询状态，不重复 POST。
3. 报告至少包含 OOS 净指标、3 个 WF 窗、成本压力、随机/MA 基线、PBO、DSR、MinTRL、容量、样本与完整身份。
4. verdict 自动落为 PASS/FAIL/INSUFFICIENT，`candidate_eligible` 与结论一致；PASS 也不得自动进入 A 池或生成订单。
5. 若发现统计实现缺陷，先加固定 fixture 的失败测试、独立提交修复，再从头重跑并废弃旧报告。

## 必跑验收

执行派工总表 V2R-R 的 Pytest、Ruff、Mypy 命令；另外计算每个最终 JSON 的 SHA-256，记录运行起止时间、task_id、代码/config/DB 身份和完整命令。
